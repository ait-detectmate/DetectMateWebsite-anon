# DetectMateWebsite

The DetectMate website, served at <https://ait-detectmate.github.io/DetectMateWebsite/>.

Two pages — home and benchmarks — built by `build.py` from templates in `src/` and data in `data/`. Standard-library Python only; no Node, no dependencies.

## Build and preview

```bash
python build.py
python -m http.server -d _site 8000
```

Then open <http://localhost:8000>. `_site/` is build output and is not committed.

## Publishing

`.github/workflows/pages.yml` builds the site on every push to `main`. Deploying is manual: **Actions → Publish site → Run workflow**.

One-time setup in the repository: **Settings → Pages → Build and deployment → Source: GitHub Actions**. On the free plan, Pages needs a public repository.

## Where things live

| Path | What |
|---|---|
| `data/detectors.json` | The detectors and their families: name, family, description, docs link |
| `data/parsers.json` | The parsers |
| `data/aggregators.json` | The alert aggregators |
| `data/benchmarks.json` | Benchmark results — see below |
| `tests/` | Unit tests: `python -m unittest discover -s tests` |
| `src/layout.html` | Header, footer, `<head>` shared by every page |
| `src/pages/*.html` | Page bodies; `{{placeholders}}` are filled by `build.py` |
| `static/css/site.css` | All styling; brand tokens at the top |
| `static/js/site.js` | The home animations and the benchmark switch bar, plots and tooltip. Pages work without it |
| `static/img/` | Logo cut from the master file as SVG: mark, wordmark, stacked lockup; a 64 px PNG of the mark as favicon fallback |

Component descriptions are paraphrased from the DetectMateLibrary docs. When a component changes, update `data/*.json`.

## Benchmarks

`data/benchmarks.json` drives the benchmarks page. It is generated by the benchmark exporter, which lives outside this repository, and is never edited by hand. Rerun the export instead.

Top-level keys:

- `_readme`: a short description of the file.
- `library_version`, `generated_at`, `environment.hardware`: what the numbers describe. They are shown in the banner above the tables.
- `log_types`: the log types, with the range of their datasets' anomaly shares in percent.
- `datasets`: the evaluated datasets (the dataset-view columns), each with its log type, source link and anomaly share.
- `not_evaluated`: detectors without results.
- `baselines`: the deep-learning detectors DetectMate is compared with.
- `results`: per detector and dataset: `precision`, `recall`, `f1`, `events_per_sec`, `no_alerts`.
- `log_type_results`: the same per log type, as a mean over its datasets.

`detector` must be an `id` from `detectors.json`; `dataset` and `log_type` must be ids from this file. The build fails on an unknown id. Where a detector raised no alerts, `precision` is `null` and `no_alerts` is `true`; the page then shows "no alerts".

The page has one frame, Detectors, with a switch bar of labelled chip groups: Show (Plot or Table), Values per (log type or dataset) and Metric (Precision, Recall, F1, events/s). Plot and Precision are the defaults. The bar appears only when JavaScript is on. Without it every table and every plot is visible. The chips in the frame have their own styles (`.frame .chip` in `site.css`).

Rows are ranked per block by the middle value of the values the block shows, highest first (fastest first for events/s); ties go to the higher mean, then to the data order. The baselines are ranked apart, below their divider. Rows without a value come last, then rows not evaluated. A table and a plot of the same view and metric list the same order. Each block has a title row, "{metric} per {view}". The plots are boxes with whiskers to the lowest and highest value, with no dots, drawn by `build.py` as inline SVG: one row per detector. x positions are percentages of the plot width, so the plots scale with the frame; the gridlines are drawn by CSS on the plot cell, at a spacing each plot table sets in its `--tick` style. Table cells show the number only.

## Brand

| Token | Value | Use |
|---|---|---|
| Blue | `#4957A5` | Primary. 6.6:1 on white — fine for text |
| Grey | `#C5C5C5` | Shapes and rules only. 1.7:1 on white — never text |
| Alert amber | `#C8700A` | Only where something fired |
| AttackMate teal | `#049899` | Links to AttackMate only |

Both colours were sampled from the earlier logo; the current master uses `#4E5AA5` and `#C6C6C6`. The right-hand corners of primary buttons and pipeline cards are cut at 45°, after the D in the mark.

Headings are set in Poppins as the closest free match to the wordmark. If the wordmark's font is known, swap it in `--display` in `site.css`.

## Before launch

- **Fonts are loaded from Google Fonts.** That sends every visitor's IP address to Google, which German courts have ruled a GDPR violation without consent. Self-host the three families (all SIL Open Font License) in `static/fonts/` and remove the `fonts.googleapis.com` links from `src/layout.html`.
