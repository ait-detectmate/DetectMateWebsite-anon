# AGENTS.md

Static website for DetectMate, served at <https://ait-detectmate.github.io/DetectMateWebsite/>. Two pages (home, benchmarks) generated by `build.py` from templates in `src/` and data in `data/`. Standard-library Python only: no Node, no dependencies, and none should be added.

## Commands

```bash
python build.py                        # writes _site/ (wiped and rebuilt every run)
python -m unittest discover -s tests   # the tests (they rebuild _site/ too)
python -m http.server -d _site 8000    # preview at http://localhost:8000
```

The tests (`tests/test_build.py`) check that both pages build, that relative links resolve, that no combinations are left, and the detector links and tags on the Benchmarks page; there is no linter. To check a change, run the tests and the build (it fails on any unfilled placeholder) and look at the page in the preview.

`.github/workflows/pages.yml` runs the tests, then the build, on every push to `main`, using Python 3.12. Deploying is manual for now (Actions → Publish site → Run workflow): GitHub Pages isn't enabled yet, and the site is waiting for its own domain. `_site/` is build output and is git-ignored.

## How the build works

Templating is plain `str.replace`, in two passes:

1. **Page body.** Each `src/pages/<name>.html` gets its `{{key}}` placeholders filled from the `fills` dict in `build()`. Each value is an HTML string made by a `render_*` function from `data/*.json`.
2. **Layout.** The result goes into `{{content}}` in `src/layout.html`, which also fills `{{title}}`, `{{description}}` and `{{nav_<page>}}` from the `PAGES` dict.

Any `{{` left afterwards stops the build, so pages can't contain a literal `{{`. Pass every data value through `esc()` before it goes into HTML.

- **New placeholder:** write a `render_*` function and add it to `fills`.
- **New page:** add the template under `src/pages/`, an entry in `PAGES`, and a nav link in `layout.html`. The nav keys are hard-coded in `build()` (`home`, `benchmarks`), so a new one has to be added there too.
- **Links:** keep them relative (`static/...`, `benchmarks.html`). The site is served under the `/DetectMateWebsite/` subpath, so links starting with `/` break once deployed.

## Data

- `data/detectors.json`: `families` and `detectors`. Every detector's `family` must be a key in `families`, or the build fails with a `KeyError`. A family's `label` is the detector's tag on the Benchmarks page. `paper` is optional.
- `data/parsers.json`: `parsers`.
- `data/aggregators.json`: `aggregators`, in the shape of `parsers.json`.
- Each component has `id`, `name`, `description` and `docs`. Detectors also have `family` and `training`. The home page shows how many there are of each; a detector's name on the Benchmarks page links to its `docs`.
- Component descriptions are paraphrased from the DetectMateLibrary docs. When a component changes upstream, update the JSON.

## Benchmarks

`data/benchmarks.json` is generated by the benchmark exporter. Never edit it by hand: rerun the export. Its top-level keys are described in `README.md`. A result whose detector or dataset id is unknown stops the build.

The page renders every benchmark block into the HTML. The detectors are one frame (`render_frame`) holding a table and a plot for each view (log type, dataset) and metric (F1, precision, recall, events/s): 16 blocks. Without JavaScript every table and every plot is visible, each under its own heading in its own fixed-height scroll box, and the switch bar stays hidden. `static/js/site.js` unhides the bar and shows one block, then adds `is-live` to the frame. The page paints before the deferred `site.js` runs, so the inline script in `layout.html` adds `js` to `<html>` first, and until the frame is live the `html.js .frame:not(.is-live)` rules in `site.css` show what `site.js` will: the bar, the default block, and blank plots for the grow-in. If any frame is still not live at `load` (`site.js` failed), the script removes `js` and the no-JS page shows. What it reads is written by `build.py`, so change it in both:

- classes: `.frame`, `.is-live`, `.frame__bar`, `.bench-block`, `.frame__scroll`, and the rows `tr[data-row]`;
- attributes: `data-frame`, `data-switch`, `data-kind`, `data-view`, `data-metric`, `data-block-*`, `data-row`.

A new metric also needs an entry in `METRICS` in `build.py`.

Each chip group in the bar starts with a visible `.chips__label` equal to its `aria-label`. The chips in the frame are styled by the `.frame .chip` rules in `site.css`.

The plots are inline SVG drawn by `build.py` with the standard library only: no shapes or dots, whiskers to the lowest and highest value, a box from q1 to q3 at 3 or more values, and a line at the middle value. x positions are percentages of the plot width; the gridlines come from CSS on the plot cell (`::before`, spaced by the `--tick` each plot table sets). Their colours come from the CSS tokens (the `.bench--plot` rules in `site.css`), never amber: a box is not an alert. `plotMarkup` in `site.js` mirrors `render_plot` for the grow-in and the morph, so change both; the animated frame always ends on the built SVG. A switch on a plot morphs it: a row still shown slides to its new place, a new one grows in; a table never moves. `render_tip` writes each plot row's numbers into `.plot__nums`, visually hidden text in the plot cell after the SVG (a screen reader reads it), and `site.js` shows a copy of it in the `.tip` tooltip on hover or tap: change both.

Every block ranks its rows (`order_rows` in `build.py`) by the middle value of the values its plot draws, highest first, within the main group and the baselines apart. Plot and Precision are the defaults, set in `render_frame_bar`, in `site.js` and in the `html.js` rules in `site.css`: change all three.

A cell reads "no alerts" where a detector raised no alerts (precision is `null`), and "not evaluated" for a detector without results. A plot leaves out the values without alerts; a row with none left reads "no alerts". Neither label is amber: amber is only for something that fired.

## Front end

- `static/js/site.js` is progressive enhancement only. Every page has to work fully without it.
- `static/css/site.css` holds all the styling, with the brand tokens in `:root` at the top.
- Brand rules:
  - Grey `#C5C5C5` is for shapes and rules only, never text (1.7:1 contrast on white).
  - Amber (`--alert`) is used only where something fired.
  - Teal (`--attackmate`) is used only for links to AttackMate.
  - The right-hand corners of primary buttons and pipeline cards are cut at 45° (`--chamfer`), after the D in the logo.
- Table cells show the number only, as dark text, so every cell keeps 4.5:1 contrast.
- Animations (`site.js`, the `motion` helper at its top):
  - The HTML holds the final state and `site.js` only animates it. With reduced motion everything stays still, and animations pause off screen and in a hidden tab.
  - The home intro runs on `data-nav="home"` once per tab session (`sessionStorage` key `dm-intro`). The inline script in `layout.html` adds `is-intro` to `<html>` before the page paints, and `site.js` removes it in the frame the animations start. The `html.is-intro` selector list in `site.css` must match what `site.js` animates; a 3 s failsafe shows it anyway, and a `site.js` that runs too late to start before the failsafe skips the intro.
  - The home page's looping animations (the code panels and the pipeline flow) run `motion.slow(ms)`, `SLOW` (1.6) times the brisk pace they are written at; their CSS transitions scale with `--home-slow` in `site.css`, which must equal `SLOW`. The one-time intro is not slowed: the 3 s failsafe times it.
  - The header mark is inline SVG so its two halves can move; the footer mark stays an `<img>`.
- The Docs and GitHub menus in the header are `details.menu`, so they open and close without JavaScript; `site.js` only closes one when the other opens, on a press outside, when focus leaves it, and on Escape.
- The Library | Service switch on the home page is CSS-only: two radios (`#run-library`, `#run-service`) in `.run`, whose labels are styled by the `.run .chip` rules next to `.frame .chip`. Both panels share one grid cell in `.run__panels`. The Service panel (`.code--service`) uses the Library panel's classes, plus `.code__term` and `.code__tline` for its terminal.

## Open before launch

Fonts load from Google Fonts, which isn't GDPR-safe without consent. To fix, self-host the three families in `static/fonts/` and remove the `fonts.googleapis.com` links from `src/layout.html`.
